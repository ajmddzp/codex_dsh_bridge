# Interface findings and architecture

## Verified upstream interfaces

- [OpenAI plugin packaging](https://developers.openai.com/plugins/build/plugins): a portable plugin uses root `plugin.json`, root `skills/`, and root `mcp.json`. The older `.codex-plugin/plugin.json` and `.mcp.json` are compatibility forms. We use the portable format.
- [OpenAI local plugin submission](https://developers.openai.com/plugins/deploy/desktop-only): local stdio MCP uses `type: "stdio"`, `command: "node"`, and `${PLUGIN_ROOT}` in `args`. Public desktop-only local MCP submission currently requires partner approval and allowlisting. A Git-backed marketplace can distribute this plugin independently; it is not in the official public directory.
- [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli): Codex supports local stdio MCP servers and `codex mcp add` for manual connection.
- [DeepSeek Harness headless](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/bundle/headless/README.md): `dsh --profile headless --json` takes a task on stdin. NDJSON contains `session`, `status`, `tool_call`, `tool_result`, and `final`. Exit 0 is completed; exit 1 is aborted or errored. `--session-id` resumes persisted conversations in the same cwd. The isolated one-shot path creates a fresh session; the persistent subagent path saves the session ID and uses the same cwd on later turns. The stream is a projection; non-final fields can be truncated.
- [Harness headless credential behavior](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/bundle/headless/README.md#credentials): the shipped headless profile reads API-key routes from the launch environment, then invocation cwd `.env`, then `$DSH_HOME/.env`. It ignores credentials saved by the GUI unless the documented credential, authorization, and DeepSeek account consumers are re-enabled. The bridge does not require an extra key; `BRIDGE_USE_DSH_SAVED_CREDENTIALS=1` passes the bundled opt-in patch to the local launcher. Because the task cwd is a separate worktree, an uncommitted `.env` in the main checkout is not copied there.
- Local verification with the current `@deepseek-ai/dsh` package showed that Node.js 23.11 exits silently because its bin uses `import.meta.main`; Node.js 24.22 produced the documented help and a complete headless event stream. This bridge therefore specifies Node.js 24+ and rejects an empty or incomplete event stream even if the process exits 0.
- The upstream [Harness repository](https://github.com/deepseek-ai/deepseek-harness) is MIT licensed and warns that its developer preview may make breaking changes. The MCP SDK package is MIT licensed.

## Runtime

`delegate_task` validates configuration and enqueues a task in a private state directory. The stdio server forks a per-task worker. The worker creates a detached Git worktree at the repository's committed `HEAD`, starts a real `dsh` headless process with stdin, records NDJSON and stderr, gathers `git diff --binary HEAD` including untracked files, saves a result, and removes the worktree. The server returns the task ID immediately. A worker watches its parent; an unexpected parent exit marks the task interrupted and stops the agent. On server restart, unfinished records are marked interrupted and matching processes are stopped. Timeout and cancellation stop the relevant process group. Results remain queryable from the state directory.

The main checkout is never modified or merged by the bridge. Uncommitted changes in the main checkout are deliberately excluded from the task's worktree. Codex must inspect and apply the returned patch; conflicts are left to Codex. Non-Git projects, empty repositories, and unsupported worktrees are rejected with clear errors. The worktree is removed even after a failure when possible. A restart also schedules cleanup of orphaned worktrees.

## Persistent subagents

`create_deepseek_agent` saves a role, optional initial context, mode, and canonical live workspace path. It does not start Harness. Each `send_deepseek_message` starts one detached worker and one headless Harness turn, returns a turn number immediately, and records the reply, event log, and stderr. Only one turn per agent can run at a time. The first prompt supplies Codex's initial context; later prompts use the saved Harness `session_id` in the same workspace. Agent records and per-turn history survive MCP server restarts, and a running detached worker continues after MCP disconnection. The server reconciles stale running records on startup. `close_deepseek_agent` cancels an active turn and prevents new messages.

The persistent workspace is the user's actual project directory, not a worktree. This allows the agent to inspect live training logs and uncommitted changes. Write mode can edit that directory directly. Read-only mode sets Harness `DSH_PERMISSION_MODE=read-only`; write mode sets `workspace-write`. The bridge does not launch training, poll logs on a timer, or autonomously decide when to send another turn. Codex controls those steps. The persistent path also works without Git.

## Security boundary

`BRIDGE_ALLOWED_ROOTS` restricts accepted workspace paths after `realpath`. Worktree separation protects the main checkout from ordinary agent edits. It **does not restrict OS filesystem reads/writes** by DeepSeek tools. `read_only` detects worktree edits after execution but cannot stop them while running. Prompt rules and keyword checks are advisory and can be bypassed by an agent or shell command. For that reason the bridge fails closed until the operator sets `BRIDGE_ACK_HOST_ACCESS=1`. Run only with trusted repositories and a separate, restricted OS account/container if stronger isolation is required. If an API key is present in the environment, its exact bytes are redacted from stored output; key-shaped `sk-...` tokens are also redacted. Saved Harness credentials are handled by Harness, not read by the bridge. Other sensitive content produced by tools may still appear in logs. Keep the state directory private. Network access is governed by the host and DeepSeek Harness, not by this bridge.

## Limits

The one-shot task store is local JSON with atomic writes, suitable for one stdio server instance. Persistent agent records use a per-agent lock and atomic writes; multiple independent server instances have not been comprehensively validated. `get_task_result` caps the returned patch at 2 MB and points to log files for investigation. It does not parse arbitrary test framework formats; it captures relevant Harness tool-result text. A reported test result must be checked against the event log and should be rerun by Codex before applying changes. Persistent agents return replies and raw event paths; Codex must inspect live workspace changes separately.
